# 诊断指南

## 1. 诊断过程

诊断按“问题 → 核验目标 → 工具观察 → 更新判断 → 继续调查或结论”循环执行。主 Agent 统一规划、审阅和总结；Subagent 只是一次独立调查任务，最多一级，不能递归创建任务。

协同度是会话级偏好，默认值为 2（谨慎协同）。即使协同度较高，简单问题或有依赖顺序的问题也可保持串行。每轮启动时记录实际协同度；主 Agent 审阅结果后可以继续下一轮工具调用或创建新的一级调查任务。

## 2. 证据边界

结果必须区分：

- **事实**：用户提供的信息或工具返回的日志、指标、配置、代码和状态。
- **推断**：由事实支持的可能原因，必须说明依据和置信度。
- **未检查范围**：权限拒绝、超时、截断、资源不可用或尚未调查的分支。

Subagent 返回证据、来源、时间、目标对象、工具、任务状态和边界，不返回面向用户的最终答案。主 Agent 负责处理冲突、去重、补充调查和最终回答。共享资源只有在实际对象定位和调查目标一致时才能复用证据。

## 3. 调查任务

每个任务至少包含：

```text
目标、应用/实例/资源、对象定位、专家能力、拆分理由、预期信息
```

服务端必须重新校验 Scope、资源关联、权限、内部 ID 防护、取消、超时和证据预算。模型提出的任务不是授权凭证。

平台硬限制包括单轮任务数和同时执行数；达到上限、预算不足或任务失败时，主 Agent 应退回串行调查或明确说明未执行范围。

## 4. 回答结构

简单问题直接回答。一般问题按需要给出结论、关键证据、建议和未检查范围。复杂问题使用：

```text
现象 → 证据 → 判断 → 建议 → 风险/未检查范围
```

不展示隐藏思维链，不把工具调用过程冒充最终结论。没有 Evidence 的内容只能作为待验证假设。

## 5. 诊断页面和 API

诊断页面展示当前轮次的进度、工具调用、观察结果和证据引用；追问会创建新轮次，不覆盖旧结论。精选因果链只引用同一会话的 Evidence，默认关系为：

```text
原因 → 作用机制 → 现象/结果
```

相关接口：

```text
POST /api/v1/diagnosis-sessions
GET  /api/v1/diagnosis-sessions/{id}
GET  /api/v1/diagnosis-sessions/{id}/events
```

完整 API 和前端事件契约见 [design/ai-engine.md](../design/ai-engine.md)；当前项目的资源工具边界见 [integrations.md](integrations.md)。

## 6. 自举诊断故障模拟

登录后点击左侧 **WORKSPACE**，会请求 `GET <basePath>/api/v1/mock/errors`，随机返回一种模拟错误，并在主标题栏中央显示 HTTP 状态、编号和错误消息，5 秒后消失。接口仅生成 HTTP 错误和关联日志，不会真的断开依赖、耗尽连接池或修改数据。

需要复现同一种错误时，携带编号，例如：

```bash
# 使用登录接口保存的 Cookie；默认 basePath 为 /opsseek
curl -i -b cookies.txt 'http://localhost:8080/opsseek/api/v1/mock/errors?number=1007'
```

| 编号 | HTTP | 模拟场景 |
| --- | --- | --- |
| 1001 | 400 | 参数解析失败 |
| 1002 | 401 | 凭据过期 |
| 1003 | 403 | 资源访问被拒绝 |
| 1004 | 404 | 实例不存在 |
| 1005 | 409 | 资源版本冲突 |
| 1006 | 429 | 请求限流 |
| 1007 | 500 | 数据库连接池耗尽 |
| 1008 | 502 | 上游连接重置 |
| 1009 | 503 | 消息队列不可用 |
| 1010 | 504 | 上游响应超时 |

响应使用统一消息字段：模拟故障的展示码为 `error.code`（`M0001`–`M0010`），类别短码为 `error.type`（`mock_1001`–`mock_1010`），正文是 `error.message`，并包含 `error.request_id`。请求参数 `number=1001..1010` 用于选择故障，不在响应中重复返回。非法、未知或重复的编号返回 HTTP 400、展示码 `E0022` 和类别短码 `invalid_mock_number`。模拟 401 不刷新会话，也不注销用户。

通过 `request_id` 关联请求日志与错误日志；模拟错误日志包含 `mock=true` 和 `error_number`，4xx 为 WARN，5xx 为 ERROR。模拟请求会影响错误率、日志及链路监控，测试时应与真实故障区分；这些日志只能证明发生了模拟，不能证明消息所描述的底层故障真实存在。
