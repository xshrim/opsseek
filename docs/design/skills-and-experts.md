# 技能、专家与专家组

**状态：** 已确认的目标设计，实施与验收进度以 [I008](../iterations/I008-skills-experts/iteration.md) 为准。本文不表示功能已全部交付。

## 1. 目标与边界

将技能从短指令和工具白名单升级为标准 Agent Skills 包；将专家定义为可配置的专精智能体，将专家组定义为带有独立协作指令的专家组合。保留现有 Engine、Scope/RBAC、资源工具、诊断流式事件和巡检调度，不引入另一套执行框架。

这是新项目的模型重构，不要求兼容旧技能格式、旧专家接口或已有数据库。实现时更新干净初始化结构，不保留双写、旧路由别名或两套模型；测试使用隔离数据库，不自动清空开发者的数据库。PR #5 仅作参考，不合并其代码，不引入 Pi 或新的 Agent Runtime。

## 2. 领域定位

| 对象 | 回答的问题 | 保存内容 | 不负责 |
|---|---|---|---|
| Skill（技能） | 如何完成某类工作 | 标准说明、参考资料、示例、工具使用知识 | 自主派发任务、授予权限、存放连接密钥 |
| Expert（专家） | 由谁、以什么专长和边界完成 | 专家指令、技能引用、项目/应用/资源范围、工具限制 | 复制技能全文、替代资源凭据和权限系统 |
| Expert Group（专家组） | 如何协调若干专家 | 组指令、成员及职责、聚合要求 | 无条件运行全体成员、成员权限取并集 |
| Engine | 如何可靠执行 | 工具循环、授权、预算、重试、取消、事件、审计 | 把某个领域的操作手册硬编码为通用规则 |

不再区分“资源专家”和“职能专家”；专家不必绑定某一种资源。代码、文档、API、表名、权限码、事件、测试及目录统一使用 `expert`。专家组使用 `expert_group`。命名清理覆盖受维护的历史 SQL 和文档，Git 历史及第三方依赖不改写。

## 3. 标准技能包

### 3.1 格式与来源

以 [Agent Skills 规范](https://agentskills.io/specification) 的 `SKILL.md` 为源格式。最小有效包可以只有一个文件：

```text
application-diagnosis/
├── SKILL.md
├── references/
│   ├── relationships.md
│   └── tools.md
├── assets/
└── scripts/
```

`SKILL.md` 使用 YAML frontmatter 与 Markdown 正文。必填 `name`、`description`，接受 `license`、`compatibility`、字符串映射 `metadata` 及实验性的 `allowed-tools`。名称遵循规范的长度、字符和目录一致性要求；描述最多 1024 字符，compatibility 最多 500 字符。平台内部版本号不强迫标准包使用 SemVer。正文没有固定章节或输入输出 Schema 要求；正文为空可导入，但应报告无法作为有效操作说明的就绪性警告。

保留原文件字节、路径、未知 frontmatter 字段和来源信息，不把导入内容改写成平台专有 JSON。标准建议的正文长度作为提示，而不是拒绝导入的条件。平台管理字段不混进必填 frontmatter。

| 导入物 | 支持边界 |
|---|---|
| 单独 `SKILL.md` | 根据 frontmatter name 建立包；相对引用的缺失文件显示报告 |
| ZIP、tar.gz / tgz | 支持单技能目录和多技能目录；先识别候选再选择导入 |
| 仓库源代码压缩包 | 允许顶层仓库包装目录、`skills/`、`.agents/skills/`、`.claude/skills/` 等任意普通目录；按 SKILL.md 定位根，不依赖特定厂商清单 |
| `.skill` 文件 | 内容确实为 ZIP 时按 ZIP 解析，不仅依赖扩展名 |
| 厂商安装清单/远程 Git URL/嵌套压缩包 | 本迭代不自动安装、下载或递归解压；明确报告不支持 |

仓库压缩包只导入用户选中的技能子树；同一树内嵌套技能根、重复名称和大小写路径冲突须报告歧义，禁止静默覆盖。

### 3.2 安全和兼容性报告

- 上传阶段鉴权，限制压缩体积、解压累计体积、文件数量、单文件大小、路径深度；边读取边计数，不能先无限解压再校验。
- 拒绝绝对路径、`..` 越界、Windows 盘符、NUL、重复路径、符号链接、硬链接和设备文件。文件保存在数据库，不写入宿主文件系统供执行。
- 校验 YAML、字符编码、frontmatter 大小及资源消耗，拒绝重复键和会产生歧义的内容。
- 报告分为阻断错误、兼容性警告、能力说明。错误逐技能定位；确认导入时再次校验并以事务写入，失败不留下半个包。
- `scripts/` 可完整保存、下载和阅读，**不执行**；不自动安装依赖。带脚本的包应明确显示“脚本执行不支持”，不承诺完全兼容。
- 外部工具声明、网络访问需求、缺失引用、许可证和平台工具匹配情况均可查看。内容是知识材料，不是授权规则，不能覆盖安全边界或泄露其他 Scope 的材料。

### 3.3 管理数据与版本

| 记录 | 关键字段与约束 |
|---|---|
| skills | id、scope_id、identifier、显示名、说明、来源 built-in/user/imported、状态、维护人、默认已发布版本；同 Scope identifier 唯一 |
| skill_versions | skill_id、内部版本、解析后的标准元数据、内容摘要、来源摘要、兼容性报告、发布时间；发布后不可变 |
| skill_files | version_id、规范相对路径、媒体类型、大小、摘要、bytea 内容；版本内路径唯一 |

复用 PostgreSQL 与现有目录服务，不引入对象存储。管理动作包括导入预览、确认导入、查看文件、编辑自有草稿、发布版本、导出、复制、删除。重新导入显式选择新建或更新自有技能，不按名字覆盖任何现有对象。已被执行引用的发布版本保留，删除目录对象不破坏历史审计。

内置技能平台级、已发布、只读：服务端禁止更新、删除、发布替换和修改归属；前端不显示这些动作。允许复制为用户自有技能。所有用户的可见性和执行权限继续沿用 Scope/RBAC，并非平台级就绕过授权。

## 4. 内置技能体系

每个资源**类型**一个内置技能，Direct/Agent 和子类型区别在同一技能中说明，不按实例生成技能。另设跨资源的 `application-diagnosis`；现有仓库诊断说明合并进 Repository 技能，不再保留第二份代码库手册。

| 领域 | 资源类型（共 27 种） |
|---|---|
| 运行时 | Host、Docker、Kubernetes |
| 大模型 | MCPServer |
| 物料仓 | Artifact、Repository、KnowledgeBase |
| 数据库 | PostgreSQL、Oracle、MySQL、OceanBase、MongoDB、Redis、TongRDS |
| 存储池 | ElasticSearch、MinIO |
| 微服务 | Nacos、Nginx、TongHttpServer、Kafka、RabbitMQ |
| 可观测 | Prometheus、Loki、Tempo、Jaeger、Skywalking、Alertmanager |

每份技能必须具有实际用途，不能只是替换资源名的一句话模板：

1. 适用问题、触发条件、非目标、前置权限和所需关系上下文。
2. 对应工具的选择逻辑、必要参数、默认值、可选筛选、时间单位、分页和截断。
3. 结果字段、空结果与错误含义、证据关联、下一步判断和停止条件。
4. Direct/Agent、版本及接入方式差异；只读与变更边界。
5. 贴近真实工具定义的调用与结果示例；示例不能被描述为现场事实。

`SKILL.md` 保存操作方法与入口，详细工具定义放在 `references/tools.md`。工具名、输入 Schema、输出契约以已注册的 Tool Catalog 为准，可由定义生成参考部分并测试校验漂移；没有结果 Schema 时明确记录实际结果类型和限制，不伪造统一输出字段。解释性的调查步骤手工编写。

不是所有目录类型都有完整工具集：无原生工具的类型必须说明当前可通过哪些已有资源、Agent/MCP 工具取证，以及哪些能力不可用。不得为“每种类型有技能”虚构工具或借机扩展未批准的资源实现。MCP 动态工具以执行时发现和授权后的定义为准，静态文档只提供发现与选择方法。

内置源文件只有一份，随程序嵌入、幂等安装并按内容摘要发布版本；SQL 不重复存放另一套提示词。旧发布版本保留供审计引用，重复启动不重复产生版本。

## 5. 提示词分层和渐进加载

```text
平台通用规则 + 可信 current_scope + 历史与执行状态
                      ↓
本次专家 / 专家组配置与授权边界
                      ↓
可用技能目录（名称、说明、版本、兼容性摘要）
                      ↓ 按任务激活
SKILL.md → 按需读取 references / assets / scripts 文本
                      ↓
已授权工具调用 → 证据 → 回答或继续调查
```

保留在通用规则中的内容：事实和推断边界、正确使用当前 Scope 与历史、自然语言进度、工具优先级和错误处理、操作授权、输出格式、取消及预算行为。结构化子智能体结果、因果链 Schema、Engine 协议等机器契约也留在运行层，不能被用户技能替换。

从通用硬编码说明中移出：应用→实例→运行时定位、关联资源与业务库/日志/仓库绑定的用法、仓库版本与路径定位、各类资源的调查手册。分别放进应用技能和对应资源技能。

新增受控的技能激活/文件读取内部工具；服务端校验 skill:read/execute、版本是否属于本次目录、文件是否在包内。每轮激活的版本、读取路径、内容摘要写入执行事件，恢复或子任务继续使用冻结版本。重复读取可去重，但不能让恢复执行丢失已激活说明。完整文件太大时分页读取并报告截断。

`allowed-tools` 是可移植的工具需求提示，不是授权。已知声明映射到本平台明确的工具名；未知的 `Bash(...)`、`Read` 等保留并提示不支持，不能默认赋予 Shell 或全盘读取。缺省声明表示没有额外技能限制，不能错误地生成空白名单封死资源工具。声明存在但不匹配时明确报告不可用；实际授权仍由 Engine 控制。不能用一种资源类型的工具权限替代对具体资源的鉴权。

## 6. 专家与专家组模型

### 6.1 专家

专家由独立目录和不可变版本组成，字段包括名称、标识、说明、图标、Scope、来源、状态、专家指令以及以下可选绑定：

- 技能：技能 ID 和发布版本选择；执行开始解析为具体版本。
- 项目、应用、资源：明确配置的可使用对象范围。
- 工具：在既有授权内进一步收窄可用工具。

各边界区分“继承本次已授权范围”和“仅使用所选集合”，空集合不能被误解为无限权限。专家可跨资源类型，但不能跨越执行者权限。配置时验证可见性，执行时重新校验授权；权限撤销后不可沿用旧快照取得访问权。

建议表结构为 `experts`、`expert_versions`，版本中的配置以受校验 JSON 保存；需要可检索和外键保护的对象关联使用关系表。保留现有审计，不保留旧的角色/资源域硬限制。

### 6.2 专家组

专家组使用 `expert_groups`、`expert_group_versions`，保存组指令、有序成员引用及职责说明。组可以独立选择作用范围，成员不可重复，不支持组嵌套。

组协调器是一次主执行的配置，不要求用户再建立一个“管理专家”。主执行按问题选择成员，复用现有子智能体通道并共享总预算、取消和事件链。成员有独立指令及技能上下文，结果带证据、未核验项和错误；主执行负责去重、辨别冲突和汇总。单个成员失败保留其已有输出，不应抹除主执行回答或让其他成员越权补救。

避免为一般问题启动全部专家；避免将全体成员的完整提示词、所有技能文件和工具 Schema 一次性拼接。成员配置、技能版本和组版本在执行开始冻结，运行中编辑不改变正在执行的任务。

### 6.3 权限

沿用 `expert:read/manage/use`，专家组使用 `expert_group:read/manage/use`，技能沿用 `skill:read/manage/execute`。查看组不意味着可读取无权限的成员配置，使用组不意味着获得成员绑定的资源权限。

有效访问范围 = 执行者（或巡检任务身份）的实时授权 ∩ 本次任务范围 ∩ 组限制 ∩ 专家限制 ∩ 工具策略。直接选择专家时省略组限制。不同成员的权限不能合并授予任一成员。

## 7. 默认项目诊断专家

内置平台级只读 `project-diagnosis` 专家，专长是依据项目结构、应用实例和关联依赖进行调查。它引用应用技能及所需资源技能，职责是组织调查、识别证据缺口和汇总结论，不重复资源工具手册。

- 用户在诊断或巡检显式选择专家/专家组时优先使用其选择，两者互斥。
- 未显式选择且任务目标是项目或应用时，将项目诊断专家作为当前主执行的配置，不额外启动一次模型调用。
- 普通聊天、列举团队/项目、独立资源提问继续通用路径，不强制展开项目调查；当前 Scope 本身不等于用户要求分析整张拓扑。
- 项目由可信 current_scope/目标绑定解析，不能写死项目名或把项目名当团队名。
- 新增项目拓扑上下文工具或补齐现有工具：包含可见节点、应用/实例、资源类型/领域/标签、范围、绑定及依赖边；明确配置关系不等于实时调用链。实体允许无项目，不虚构其平台应用身份。
- 应用关联资源是取证入口，依据问题选用相关绑定及资源工具；资源连接配置与业务目标绑定分层，不把 DBA 登录库误当业务库，不向模型展示密码。
- 大拓扑分页并按目标裁剪；无权限/空关系/未配置与运行异常分开表达。

## 8. 接口与页面

技能页面复用公共可展开表格、向导、消息和表单校验。导入流程为“上传→技能选择与兼容性报告→目标 Scope/冲突处理→确认”；查看页显示主文件、文件树、元数据、来源、版本、能力限制和真实可用工具。内置技能明确标识只读，可作为标准示例查看或复制。

专家页面提供“专家 / 专家组”两个入口，复用现有卡片/表格，不添加资源专家/职能专家筛选。编辑指令、技能、项目、应用、资源和工具绑定时使用现有带图标选择组件，组编辑包含成员职责。诊断和巡检选择器展示可见可用的专家或组，清晰区分默认使用与用户选择。

接口沿用 `/api/v1/skills`，新增导入预览/确认、文件、导出和版本接口；专家使用 `/api/v1/experts`、`/api/v1/expert-groups`。错误定位到字段或包路径；服务器拒绝只读修改和越权操作，不能仅靠隐藏按钮。禁止将导入正文以未经安全处理的 HTML 展示。

## 9. 切换、回归与完成定义

先发布本设计与 I008 文档，再从已推送 main 建立实施分支。顺序为标准包模型→专家命名清理→内置技能→专家与组→运行集成及 UI→全链路回归。每一步维护可运行的中间状态，删除被替代路径，避免并行保留两套选择器或提示词来源。

干净数据库必须同时保留 main 已有的 MongoDB、应用监听地址、唯一约束、权限、通知等全部结构和数据种子；不得直接采用 PR 中的初始化 SQL。不会修改 Makefile、Dockerfile、Compose 的部署语义；如实际需要改动，须在对应任务记录理由并验证构建。

验收至少覆盖：标准包往返、恶意归档和大小限制、内置只读、27 类型完整性、工具文档漂移、权限交集、渐进加载、冻结版本、项目路由、专家组部分失败与取消、巡检执行、历史输出保留、SQL/API/前端检查。未连接真实模型和外部资源的验证必须如实标注，不能把模拟测试写成现场验收。

本迭代不实现脚本运行沙箱、远端技能市场、自动依赖安装、专家组递归、另一套工作流引擎或所有资源的新增工具。有关能力缺口在技能兼容性报告和验收遗留事项中列出。
