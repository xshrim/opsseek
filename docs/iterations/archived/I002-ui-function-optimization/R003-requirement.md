## 背景与目标

统一 API 错误与前端公共消息的可检索消息码，在公共消息组件中以标签展示 HTTP 状态码和内部消息码，并简化组件样式。`error.code` 沿用字段名，但值统一替换为展示码，不再保留旧机器码。

## 消息码规则

| 前缀 | 类型 | 示例 |
| --- | --- | --- |
| `E` | API/系统错误 | `E0001` |
| `M` | 模拟故障 | `M0001` |
| `S` | 成功 | `S0001` |
| `W` | 警告 | `W0001` |
| `I` | 一般提示 | `I0001` |

所有展示码固定为一个大写前缀加四位数字，且各前缀均从 `0001` 开始。`E0045` 保留为未知错误兜底码。HTTP 状态码不是内部消息码，单独以三位数字显示。两者同时存在时按 HTTP 状态码、内部消息码顺序展示。相同类型的标签使用相同颜色。`error.code` 是展示码，`error.type` 保留短类别码供用户报告。展示码需保持稳定分配，因此服务端仍维护类别到展示码的映射。

## 边界与风险

- 不改变 HTTP 状态、业务错误内容和权限行为。
- 错误响应使用 `{ "error": { "code": "E0001", "type": "invalid_request", "message": "...", "request_id": "..." } }`；`code` 是五位展示码，`type` 是可供用户报障的类别短码；不返回 `error.number` 或 `error.message_code`。
- 展示消息码用于定位稳定的错误类别，不代替 `request_id`、日志堆栈或具体消息。
