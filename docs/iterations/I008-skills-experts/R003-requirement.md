# I008-R003 专家、专家组与统一命名

**迭代：** [I008](iteration.md)
**需求状态：** 待规划
**验收报告：** [R003 验收](R003-requirement-acceptance.md)

## 1. 需求背景

专家需要表达专长、指令与实际可用边界，不再受旧资源域和主从角色分类限制。专家组是独立协作配置，不是指令简单拼接。

## 2. 目标与范围

全仓英文命名清理，专家和组目录/版本/绑定、Scope 权限、CRUD 与界面。

权威模型与边界见 [设计文档](../../design/skills-and-experts.md)，本文件仅记录交付任务。

## 3. 非目标

旧接口别名、兼容数据库、组嵌套、专家突破执行者权限、按每种资源实例创建专家。

## 5. 任务说明

### T01 统一专家英文命名

**实施范围：** 重命名 Go 包/类型、前端目录/类型/API、SQL 表字段索引、权限事件、种子、测试及维护文档；不改写 Git 历史和第三方依赖。

**验收标准：** 维护文本与路径扫描旧词为零；Go 编译/定向测试、前端检查、路由权限与 SQL 引用验证；历史归档只作术语勘误，不改写验收结论。

**风险和回滚：** 在实施分支按任务检查提交；涉及模型改变时使用隔离数据库验证，回滚代码不承诺兼容新结构。不得为通过测试绕过权限或修改历史验收证据。

### T02 专家版本与范围模型

**实施范围：** 专家保存指令、技能版本、项目/应用/资源和工具边界；区分继承范围与仅所选集合，发布不可变，内置对象只读。

**验收标准：** 配置和执行双重鉴权；空集合、跨 Scope、失效引用、权限撤销测试；版本变动不改变已冻结执行。

**风险和回滚：** 在实施分支按任务检查提交；涉及模型改变时使用隔离数据库验证，回滚代码不承诺兼容新结构。不得为通过测试绕过权限或修改历史验收证据。

### T03 专家组模型与权限

**实施范围：** 添加组指令、成员版本及职责、组范围、独立权限和 CRUD；无重复成员/递归组；成员不可见或不可用时明确处理。

**验收标准：** 服务及 API 测试覆盖重复/无效成员、发布引用、权限交集、内置防写、组使用不授予成员/资源权限。

**风险和回滚：** 在实施分支按任务检查提交；涉及模型改变时使用隔离数据库验证，回滚代码不承诺兼容新结构。不得为通过测试绕过权限或修改历史验收证据。

### T04 专家与组管理页面

**实施范围：** 专家/专家组分开管理；选择技能、项目、应用、资源与工具，组编辑成员职责；删除旧专家类型和角色限制控件。

**验收标准：** 前端检查/组件测试与交互验证覆盖只读、空限制、授权选择、版本和提交错误；复用公共 UI 样式。

**风险和回滚：** 在实施分支按任务检查提交；涉及模型改变时使用隔离数据库验证，回滚代码不承诺兼容新结构。不得为通过测试绕过权限或修改历史验收证据。
